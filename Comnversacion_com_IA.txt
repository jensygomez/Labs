🚀 Flujo de Comunicación
Cliente LXC (cada 30s) → Petición HTTP → Fakecloud ELB (DNS resuelve via Route53)

Fakecloud ELB → Distribuye tráfico entre VM App1, App2, App3 (round-robin)

VMs App → Almacenan datos persistentes en VM Storage (NFS on-premise)

VMs App → Conectan a Fakecloud RDS (PostgreSQL real en Docker) y a Fakecloud S3 (para objetos)

Fakecloud → Simula todos los servicios de AWS con credenciales dummy (test/test)

✅ Ventajas de esta Arquitectura
Aspecto	Beneficio
Realismo	Fakecloud usa contenedores reales para RDS y Lambdas
Aislamiento	Cada VM tiene su propio kernel, SELinux, LVM, systemd
Ligereza	LXC para el cliente (casi sin overhead)
Troubleshooting	Puedes romper SELinux, LVM, red, discos en VMs sin afectar al host
Portabilidad	Todo se recrea con terraform apply en cualquier laptop
Híbrido	Simulas integración on-premise (VMs) + nube (Fakecloud)

📋 LISTA COMPLETA DE INCIDENTES
A. SERVICIOS Y APLICACIONES (8 escenarios)
#	Nombre	Lo que rompe	Lo que aprendes	Pistas falsas
A1	"El servicio no responde"	systemctl stop nginx (detienes el servicio web)	Verificar estado de servicios con systemctl, revisar logs en /var/log/nginx/	"El firewall está bloqueando el puerto 443" (mentira)
A2	"El proceso se cae solo"	Crontab que mata el proceso cada 5 min	Revisar cron jobs con crontab -l, systemd timers	"Es un problema de memoria" (pista falsa)
A3	"Puerto ocupado"	Levantas otro servicio en el mismo puerto	Usar ss -tulpn, netstat, lsof -i:80	"El firewall lo está bloqueando"
A4	"Systemd unit corrupta"	Rompes el archivo /etc/systemd/system/app.service	Revisar sintaxis de units, usar systemd-analyze verify	"El servicio no está instalado"
A5	"Logs gigantescos"	Rota logs sin comprimir, llenando el inodo	Configurar logrotate, revisar journalctl -u	"Es un problema de disco" (verdad pero parcial)
A6	"El proceso no inicia por dependencia"	Desactivas network.target como dependencia	Entender Wants=, After=, Requires= en systemd	"El puerto está ocupado"
A7	"Application crash loop"	Modificas el archivo de configuración con sintaxis inválida	Usar strace -p <pid>, revisar logs de aplicación	"El servicio está detenido"
A8	"No hay suficiente file descriptors"	Modificas LimitNOFILE=10 en la unit	Aprender sobre ulimit -n, cat /proc/sys/fs/file-max	"Es un problema de memoria"
B. SISTEMA DE ARCHIVOS Y DISCOS (8 escenarios)
#	Nombre	Lo que rompe	Lo que aprendes	Pistas falsas
B1	"Disco lleno"	Creas archivo de 900 MB en /var	Usar du -sh *, find / -size +100M, df -h	"Es un problema de inodos" (verdad pero secundario)
B2	"Inodos agotados"	Creas 500,000 archivos vacíos en /tmp	df -i, find / -type f | wc -l	"El disco está lleno"
B3	"LVM con espacio sin asignar"	Creas LV pero no extiendes el FS	lvextend, resize2fs / xfs_growfs	"El disco está corrupto"
B4	"Partición corrupta"	Corrompes la superbloque del disco LVM	Usar fsck -y, recuperar superbloque	"Es un problema de mount"
B5	"Montaje fallido"	Eliminas el punto de montaje	mount -a, findmnt, revisar /etc/fstab	"El disco no existe"
B6	"Quota excedida"	Configuras quota muy baja en el usuario	Aprender quota, repquota, edquota	"El disco está lleno"
B7	"RAID software degradado"	Marcas un disco como failed en mdadm	cat /proc/mdstat, mdadm --detail, mdadm --manage	"El disco no se detecta"
B8	"ACLs bloqueando acceso"	Pones ACL restrictiva en /var/www	getfacl, setfacl, entender ACLs	"Es un problema de permisos Unix" (parcial)
C. RED Y CONECTIVIDAD (8 escenarios)
#	Nombre	Lo que rompe	Lo que aprendes	Pistas falsas
C1	"IP conflict"	Asignas la misma IP estática que otra VM	ip addr, arp-scan, revisar DHCP	"El switch está mal"
C2	"DNS no resuelve"	Corrompes /etc/resolv.conf	dig, nslookup, host, revisar systemd-resolved	"El servicio está caído"
C3	"Firewall bloquea todo"	iptables -P INPUT DROP	iptables -L -n -v, tcpdump, nmap	"El servicio no está escuchando"
C4	"Ruta por defecto eliminada"	ip route del default	ip route, ping -I, traceroute	"El gateway está caído"
C5	"MTU incorrecto"	Configuras MTU=500 en la interfaz	ip link set mtu, ping -M do -s	"Es un problema de firewall"
C6	"ARP poisoning"	Añades entrada ARP falsa	arp -a, ip neigh, arping	"La MAC es incorrecta"
C7	"TCP window scaling"	Desactivas TCP window scaling	sysctl net.ipv4.tcp_window_scaling, tcpdump	"Es un problema de ancho de banda"
C8	"Bridge roto"	Desconectas la interfaz del bridge LXD	brctl show, ip link set, revisar LXD config	"La VM no tiene red"
D. SEGURIDAD Y SELINUX (6 escenarios)
#	Nombre	Lo que rompe	Lo que aprendes	Pistas falsas
D1	"SELinux en modo enforcing bloquea"	chcon -t wrong_t /var/www/html/index.html	audit2why, ausearch -m avc, sealert	"Es un problema de permisos"
D2	"SELinux booleano incorrecto"	Desactivas httpd_can_network_connect	getsebool -a, setsebool -P	"El firewall bloquea"
D3	"SELinux context persistente"	Restauras contexto incorrecto con restorecon	semanage fcontext, restorecon -v, matchpathcon	"El archivo no existe"
D4	"SELinux permisivo bloquea aplicación"	Pones el proceso en un dominio incorrecto	ps -Z, ls -Z, chcon --type	"El proceso está caído"
