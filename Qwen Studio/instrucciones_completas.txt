## CRITICAL CHANGE: DIRECT VALIDATION (NO EVIDENCE FILE)

**From Mock #14 onwards**, we are adopting a **new validation approach** that is simpler, faster, and more robust:

- **No node03**: Only node01 (control) and node02 (server).
- **No `generate-evidence.sh`**: No evidence files are created.
- **Direct SSH validation**: `validate.sh` connects directly to node02 and runs live checks using `sshpass`.

### Why this approach?
- Eliminates parsing errors (no `sed` block extraction).
- Works with any Linux distribution (no file format assumptions).
- Faster to develop and debug.
- More reliable across different Ubuntu versions.

### Validator Structure (mandatory for all new mocks)

The `validate.sh` script must follow this pattern:

```bash
#!/bin/bash
SSH_OPTS="-o StrictHostKeyChecking=no -o ConnectTimeout=5"
PASS="caleston123"
NODE="bob@node02"

run_remote() {
    sshpass -p "$PASS" ssh $SSH_OPTS "$NODE" "$1" 2>/dev/null
}

# Print result with colored output
print_res() {
    local n=$1; local name=$2; local pts=$3; local pass=$4; local desc=$5; local out=$6
    echo -e "\n${CYAN}┌─ TASK $n: $name ($pts pts) ─${RESET}"
    echo -e "${YELLOW}   $desc${RESET}"
    if [ "$pass" -eq 1 ]; then
        echo -e "   ${GREEN}✅ +$pts pts${RESET}"
        TOTAL=$((TOTAL + pts)); PASS_COUNT=$((PASS_COUNT + 1))
    else
        echo -e "   ${RED}❌ +0 pts${RESET}"
        echo -e "   ${YELLOW}   Output obtained:${RESET}"
        echo "$out" | head -n 3 | sed 's/^/   /'
        FAIL_COUNT=$((FAIL_COUNT + 1))
    fi
}

# Example validation for a package installation
out=$(run_remote "dpkg -l htop 2>/dev/null")
if echo "$out" | grep -q "htop"; then ok=1; else ok=0; fi
print_res 1 "htop install" 3 $ok "Package installed" "$out"
