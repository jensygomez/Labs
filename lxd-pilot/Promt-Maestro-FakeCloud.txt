## INFRASTRUCTURE — HYBRID (LXC + fakecloud)

### On‑Premise Tier (LXC Containers)
- **Technology:** LXD/LXC containers (lightweight, fast boot, low resource usage)
- **Nodes:** 3 containers (`server01`, `server02`, `server03`) — the application fleet
- **Resource budget:** 512MB RAM / 1 vCPU per container
- **Network:** Static IPs in `10.45.223.0/24` subnet (`101`, `102`, `103`)
- **OS:** AlmaLinux 9 (RHEL-compatible)
- **User:** root (SSH key authentication, no password)
- **SSH Key:** `~/.ssh/id_lxd_fleet` (injected via cloud-init or Terraform)
- **Role:** Run the application stack; one of them will carry the fault in each incident.

### Cloud Tier (fakecloud — Local AWS Emulator)
- **Technology:** **fakecloud** (LocalStack‑compatible emulator) running in its own LXC container or as a service on the host.
- **Services emulated:**
  - **S3** — object storage (buckets, objects, lifecycle policies)
  - **RDS** — relational database (PostgreSQL or MySQL)
  - **Route53** — private DNS resolution (e.g., `db.app.internal` → RDS endpoint)
  - **IAM** — identity and access management (users, roles, policies)
  - **CloudWatch** (optional) — basic metrics and alarms
- **Resource budget:** 1‑2GB RAM, 1‑2 vCPU (can be a container or a service on the host)
- **Access:** AWS CLI configured with `--endpoint-url` pointing to fakecloud.

### Monitoring Tier
- **Technology:** Prometheus + Alertmanager (or a lightweight alternative like `monit` + `node_exporter`)
- **Deployment:** As an LXC container or a systemd service on the host.
- **Role:** Scrape metrics from:
  - LXC nodes (CPU, memory, disk, network, custom app metrics)
  - fakecloud services (S3 bucket sizes, RDS connections, IAM usage)
- **Alerting:** Generates real alerts (simulated PagerDuty tickets) that appear in the MOTD or via a local webhook.

### Networking & DNS
- **Subnet:** `10.45.223.0/24` (LXD bridge)
- **Gateway:** `10.45.223.1`
- **DNS Resolution:**
  - LXC nodes use Route53 (fakecloud) for internal service discovery.
  - Example: `db.app.internal` resolves to the RDS endpoint (10.45.223.x).
- **Static IPs:** `server01=.101`, `server02=.102`, `server03=.103`
- **fakecloud services:** Get IPs in the same subnet (e.g., `.104` for S3, `.105` for RDS, `.106` for monitoring).

### Storage
- **Application logs:** Written to S3 buckets via AWS CLI (simulated).
- **Backups:** Stored in S3 buckets.
- **Shared state:** RDS database holds application state (simulated).

## TERRAFORM — The Single Source of Truth

All infrastructure is defined as **Terraform code** and deployed/destroyed with a single command.

**Key features:**
- **Provider:** `terraform-lxd/lxd` + `local` (for fakecloud setup).
- **Modules:** Separate modules for LXC nodes, fakecloud services, monitoring, and networking.
- **State:** Local file (or remote backend if desired).
- **Provisioners:** cloud‑init + remote‑exec to set up SSH keys, packages, and initial configurations.
- **Inventory:** Terraform generates a dynamic Ansible inventory (`inventory.ini`) after deployment.

**Workflow:**
1. `terraform apply -auto-approve` → < 2 minutes → full hybrid environment.
2. Run incident injection script (`./incidentes/inc-XXX.sh`).
3. Triage & remediate (manually, then with Ansible).
4. `terraform destroy -auto-approve` → clean slate for next incident.

## INCIDENT TOPOLOGY & PHILOSOPHY

### Fixed Topology (for all incidents)
- **Always 3 LXC nodes** (server01–03). One carries the fault (your choice, hidden).
- **Always fakecloud** (S3, RDS, Route53, IAM) available for incidents that require cloud services.
- **Always monitoring** (Prometheus) scraping all components.
- **Optional extra nodes** (server04, server05, etc.) can be added via Terraform variables if an incident requires a dedicated backend (e.g., an NFS server), but the default is the hybrid topology.

### Incident Classification (by domain)
- **Linux‑only:** Fault resides entirely in the LXC node (systemd, filesystem, SELinux, networking, etc.).
- **Cloud‑only:** Fault resides in a fakecloud service (S3 bucket policy, RDS max connections, IAM role missing, DNS misconfiguration).
- **Hybrid:** Fault spans both domains (e.g., an app cannot write to S3 because its IAM role expired, causing local logs to fill up disk on the LXC node).

### Red Herrings & Previous Shift Notes
- Always included in the MOTD ticket.
- Must be plausible and physical (e.g., "We saw error X and restarted service Y, but it didn't help").
- Must never hint at the actual root cause or the affected node.

Same as before: the incident ticket appears in `/etc/motd` on **all LXC nodes** (or only on affected ones, depending on the scenario). The ticket includes:

- Reported by (e.g., Zabbix Monitoring) and timestamp
- Summary (1‑2 lines)
- Full description with symptoms, impact, and red herrings
- Resolution criteria (numbered list)
- Clear instruction to:
  1. Resolve manually first.
  2. Then create TWO Ansible playbooks (triage + remediation) designed for a 1000‑server fleet.

## THE 50 INCIDENTS (Updated for Hybrid Cloud)

**Incidents 001‑010** are already built, run, and resolved (Linux‑only, simple). They serve as reference.

**Incidents 011‑050** are designed with the hybrid architecture in mind. Each has a **real‑world production problem**, a **domain classification**, and a **topology requirement**.

### 🟡 Level 4/10 (011-020) — Medium cascade, 2 false negatives

#### inc-011-storage-lvm-growfs-missing (Linux‑only)
- **Problem:** LVM volume extended but filesystem not grown (classic storage ops mistake).
- **Topology:** 3 LXC nodes + fakecloud S3 for backup logs. One node has the issue.
- **Fault:** lvextend done but no resize2fs/xfs_growfs.
- **False negatives:** `lvs` shows free space; `df` shows 100% but `du` doesn't explain the total size.

#### inc-012-network-resolv-conf-overwritten (Linux‑only)
- **Problem:** NetworkManager overwrites `/etc/resolv.conf` on reboot, removing custom DNS entries.
- **Topology:** 3 LXC nodes + Route53 (fakecloud) for internal DNS. One node loses its custom resolver.
- **False negatives:** Ping by IP works; only name resolution fails.

#### inc-013-users-sudoers-syntax-error (Linux‑only)
- **Problem:** Syntax error in `/etc/sudoers.d/` drop‑in breaks sudo for a group.
- **Topology:** 3 LXC nodes. One has the corrupt file.
- **False negatives:** Root via SSH key still works; problem only for admin group.

#### inc-014-perf-oom-killer-no-swap (Linux‑only)
- **Problem:** No swap configured; heavy cron job triggers OOM killer, killing a critical service.
- **Topology:** 3 LXC nodes. One has no swap.
- **False negatives:** Service has `Restart=always` and restarts quickly, hiding the kill.

#### inc-015-logs-cron-missing-path (Linux‑only)
- **Problem:** Cron job fails because `PATH` doesn't include the binary.
- **Topology:** 3 LXC nodes. One has a different/minimal `PATH` in crontab.
- **False negatives:** Script works manually; only fails via cron.

#### inc-016-apps-tls-renew-script-permissions (Linux‑only)
- **Problem:** Certbot renewal hook loses execute bit after deploy.
- **Topology:** 3 LXC nodes + fakecloud S3 (for cert backup). One node has the hook without `+x`.
- **False negatives:** HTTPS still works until expiry; no visible error.

#### inc-017-backup-missing-pipefail-zero-bytes (Linux‑only + S3)
- **Problem:** `tar | gzip` without `pipefail`; tar fails but gzip exits 0 → empty backup uploaded to S3.
- **Topology:** 3 LXC nodes backing up to S3 (fakecloud). One has the broken script.
- **False negatives:** Exit code 0, log says "backup OK", but S3 object size is 0.

#### inc-018-cross-incorrect-bind-address (Linux‑only)
- **Problem:** Service binds to `127.0.0.1` instead of `0.0.0.0` — works locally, fails from other nodes.
- **Topology:** 3 LXC nodes. One has the misconfigured bind.
- **False negatives:** `curl localhost` works; service shows "active (running)".

#### inc-019-boot-grub2-menuentry-deleted (Linux‑only, single‑node, requires VM)
- **Problem:** GRUB2 entry corrupted/deleted → system won't boot.
- **Topology:** Single VM (not LXC) — use KVM for this one.
- **False negatives:** None — it's a boot failure.

#### inc-020-storage-nfs-rpc-firewall-blocked (Linux‑only)
- **Problem:** Firewalld blocks RPC/NFS port → mounts are stale/intermittent.
- **Topology:** 3 LXC nodes + an NFS server (could be server04 or fakecloud EFS). One node has the firewall rule missing.
- **False negatives:** `rpcinfo -p` on server looks fine; only the affected client can't mount.

### 🟠 Level 5/10 (021-030) — Long cascade, cross‑domain, 2+ false negatives

#### inc-021-network-firewall-rich-rules-subnet (Linux‑only)
- **Problem:** Rich rule points to old subnet after migration → blocks new traffic.
- **Topology:** 3 LXC nodes. One has the stale rich rule.
- **False negatives:** `firewall-cmd --list-all` looks normal; service itself is healthy.

#### inc-022-users-selinux-web-context (Linux‑only)
- **Problem:** Web content copied without correct SELinux context (`httpd_sys_content_t`) → 403 despite correct Unix permissions.
- **Topology:** 3 LXC nodes serving same content. One has wrong context.
- **False negatives:** `ls -l` permissions are identical.

#### inc-023-perf-disk-io-swap-thrashing (Linux‑only)
- **Problem:** Memory pressure forces aggressive swapping, causing I/O thrashing.
- **Topology:** 3 LXC nodes. One has undersized memory for its load.
- **False negatives:** CPU% looks normal; `free -h` doesn't tell the full story without `vmstat`/`iostat`.

#### inc-024-logs-rsyslog-logrotate-no-restart (Linux‑only)
- **Problem:** Logrotate rotates log but doesn't send HUP to rsyslog → process writes to old inode.
- **Topology:** 3 LXC nodes. One has missing `postrotate` directive.
- **False negatives:** rsyslog is "active (running)" but writing to nowhere.

#### inc-025-apps-db-max-connections-zombies (Hybrid — RDS)
- **Problem:** `max_connections` on RDS (fakecloud) exhausted by zombie/idle connections → new connections rejected.
- **Topology:** 3 LXC nodes connecting to RDS (fakecloud). One node has a connection leak.
- **False negatives:** RDS is "up" and accepts manual connections; other nodes work fine until pool fills.

#### inc-026-backup-lvm-snapshot-merge-failure (Linux‑only)
- **Problem:** LVM snapshot used for backup never merged/removed → grows and fills volume.
- **Topology:** 3 LXC nodes. One has orphaned snapshot.
- **False negatives:** Backup "completed OK"; problem appears later on the origin volume.

#### inc-027-cross-cascade-disk-logrotate-selinux (Hybrid — disk + SELinux)
- **Problem:** Disk nearly full → logrotate fails midway → SELinux contexts get corrupted.
- **Topology:** 3 LXC nodes + S3 for log archiving. One has the cascade.
- **False negatives:** SELinux errors appear only after logrotate failure.

#### inc-028-boot-restart-always-failing-script (Linux‑only)
- **Problem:** Service in crash‑loop with `Restart=always`; monitoring sees it as "running" due to PID file.
- **Topology:** 3 LXC nodes. One in crash‑loop.
- **False negatives:** `systemctl status` may show "activating (auto‑restart)" interpreted as healthy.

#### inc-029-storage-filesystem-remount-readonly (Linux‑only)
- **Problem:** Filesystem remounts as read‑only after journal errors; cached writes appear successful.
- **Topology:** 3 LXC nodes. One remounted RO.
- **False negatives:** Writes appear successful until flush.

#### inc-030-network-nat-interface-renamed (Linux‑only)
- **Problem:** Interface name changes (e.g., eth0→ens3) after kernel update → NAT rules broken.
- **Topology:** 3 LXC nodes. One has stale NAT rules.
- **False negatives:** Interface is UP with correct IP; only NAT rules are broken.

- **Topology:** 3 LXC nodes. One has wrong context.

#### inc-032-perf-high-load-nfs-uninterruptible (Linux‑only)

#### inc-033-logs-ansible-drift-ausearch (Linux‑only)

#### inc-034-apps-port-conflict-systemd-socket (Linux‑only)

#### inc-035-backup-partial-restore-selinux (Linux‑only)

#### inc-036-boot-emergency-mode-initramfs-fstab (Linux‑only, single‑node, VM)

#### inc-037-storage-fsck-corrupt-inodes (Linux‑only, single‑node, VM)

#### inc-038-network-mtu-mismatch-latency (Linux‑only)
- **Problem:** MTU mismatch between two nodes causes fragmentation; small pings work, large transfers fail.
- **Topology:** 2 explicit nodes within the fleet.

#### inc-039-users-pam-faillock-account-locked (Linux‑only)
- **Problem:** `pam_faillock` locks a service account after repeated failed attempts.
- **Topology:** 3 LXC nodes. One has the account locked.
- **False negatives:** Password/key is correct; the lock is temporary.

#### inc-040-perf-memory-leak-systemd-limits (Linux‑only)
- **Problem:** Memory leak hits `MemoryMax` cgroup limit → service gets killed/restarted periodically.
- **Topology:** 3 LXC nodes. One has the leak.
- **False negatives:** Service "recovers" each time; host memory looks normal (limit is per‑cgroup).

### 🟣 Level 7/10 (041-050) — Major incidents, "everything looks fine" is the main false negative, 3+ FN

#### inc-041-logs-journal-corrupt-machine-id (Linux‑only, single‑node, VM)
- **Problem:** Journal/machine‑ID corruption breaks logging and identity‑dependent services.
- **Topology:** Single VM.
- **False negatives:** None — journal corruption.

#### inc-042-apps-rootless-container-subuid-cgroups (Linux‑only)
- **Problem:** Rootless Podman container fails due to subuid/subgid range or cgroup v2 delegation.
- **Topology:** 3 LXC nodes. One has the misconfigured rootless container.
- **False negatives:** Container appears created but fails to start.

#### inc-043-boot-systemd-race-condition (Linux‑only)
- **Problem:** Race condition between two systemd units without proper ordering → intermittent failure on some boots.
- **Topology:** 3 LXC nodes; reboot repeatedly to expose the race.
- **False negatives:** Works on some boots, fails on others.

#### inc-044-storage-lvm-filter-metadata-backup (Linux‑only, single‑node, VM)
- **Problem:** LVM filter misconfigured → cannot see/activate a VG; requires `vgcfgrestore`.
- **Topology:** Single VM.
- **False negatives:** None — storage unavailable.

#### inc-045-network-asymmetric-routing-nftables (Linux‑only)
- **Problem:** Asymmetric routing combined with nftables state discards return traffic.
- **Topology:** 2 explicit multi‑homed nodes within the fleet.
- **False negatives:** Outgoing traffic works; incoming response is dropped.

#### inc-046-users-default-acls-umask-pam (Linux‑only)
- **Problem:** Default ACLs + `umask` from `pam_umask` produce files that a group cannot read, despite owner/group looking correct.
- **Topology:** 3 LXC nodes. One has the wrong umask/ACL inheritance.
- **False negatives:** `ls -l` looks normal; need `getfacl` to see the issue.

#### inc-047-perf-tcp-conntrack-table-full (Linux‑only)
- **Problem:** `nf_conntrack` table fills under load → new connections dropped silently.
- **Topology:** 3 LXC nodes under real load. One has conntrack limit reached.
- **False negatives:** App logs don't show errors; only `conntrack -S` reveals the limit.

#### inc-048-cross-multi-layer-firewall-selinux-proxy (Hybrid — firewalld + SELinux + proxy)
- **Problem:** Three security layers interact poorly: firewalld blocks a port, SELinux denies the proxy, and the proxy misconfiguration masks both.
- **Topology:** 3 LXC nodes + fakecloud (for external endpoints). One has the cascade.
- **False negatives:** Each layer alone looks "normal"; the combination causes the failure.

#### inc-049-backup-db-lock-io-starvation-oom (Hybrid — RDS + local disk)
- **Problem:** Backup job takes DB lock → queries queue → I/O starvation → OOM on the LXC node.
- **Topology:** 3 LXC nodes + RDS (fakecloud). One node suffers the cascade.
- **False negatives:** DB is up; queries work initially; OOM is the final symptom.

#### inc-050-cross-cluster-split-brain-ntp-quorum (Hybrid — DNS + time sync)
- **Problem:** NTP drift breaks quorum of a distributed cluster (simulated with corosync/pacemaker or a custom app). Split‑brain occurs.
- **Topology:** 3 LXC nodes + Route53 (fakecloud) for service discovery. One node has clock drift.
- **False negatives:** Network is up; services respond; quorum loss is only detected by cluster logs.
